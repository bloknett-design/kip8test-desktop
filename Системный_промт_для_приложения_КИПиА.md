## ⚠️ ВАЖНО: это тестовый десктоп (Electron)

Этот промт описывает **тестовый** десктоп-репозиторий `kip8test-desktop` — Electron-сборку, которая зеркалирует PWA `kip8test`. В десктопе нет своего `index.html` — он синхронизируется из `kip8test` через GitHub Action `sync-to-desktop.yml`.

**Критические отличия от PWA-репозитория kip8test:**
- `index.html` — точная копия PWA `kip8test` (со всеми `kip8test:`-префиксами и `isolateLocalStorage()`), грузится локально через Electron BrowserWindow
- **НЕТ** `manifest.json`, `sw.js`, `.nojekyll`, `.well-known/` — эти PWA-файлы не нужны в Electron
- **НЕТ** `scripts/` — синхронизация данных идёт в PWA-репозитории
- **СВОИ**: `electron/main.js` (точка входа Electron с autoUpdater + `cleanCacheOnStartup()` Task 129), `charts-desktop.js` (Task 146, только в Electron), `devices-table-desktop.js` (Task 148, только в Electron), `package.json` (appId `com.bloknett.kipia.test`, productName `KIPiA Test`, version 2.1.7+)
- Версия Electron-приложения: `2.1.7` (отдельная нумерация от PWA `kip8test`)
- Деплой: через тег `v*` (сборка + GitHub Releases через `build-desktop.yml`); обновление — через `electron-updater` autoUpdater
- **НЕ СОБИРАЕТСЯ APK** — это десктоп, не мобильное приложение
- **Изменения в `electron/main.js`, `package.json`, `charts-desktop.js`, `devices-table-desktop.js`** делаются прямо здесь (это тестовый десктоп — здесь ведётся активная разработка десктоп-специфичных модулей). Изменения в `index.html` — через правки в `kip8test` (PWA), затем автоматически синхронизируются сюда через `sync-to-desktop.yml`

## 🗺️ Связь между 4 репозиториями

```
                            ┌─────────────────────────────────────┐
                            │        ИСТОЧНИК ПРАВОК              │
                            │   kip8test  →  kip8                  │
                            │   (test PWA)   (боевой PWA, APK)     │
                            └────────────┬────────────────────────┘
                                         │ GitHub Action
                                         │ sync-to-desktop.yml
                                         │ (по пуше в index.html)
                                         ↓
                            ┌─────────────────────────────────────┐
                            │        ДЕСКТОП-ЗЕРКАЛА              │
                            │   kip8test-desktop  ←  kip8test     │
                            │   kip8-desktop       ←  kip8        │
                            │   (Electron, своя нумерация v2.1.x) │
                            └─────────────────────────────────────┘
```

| Репозиторий | Тип | Кэш PWA | Версия десктопа | Назначение |
|-------------|-----|---------|------------------|------------|
| `kip8test` | PWA | `kipia-test-v445` | — | Активная разработка, проверка перед боем |
| `kip8` | PWA + APK | `kipia-v392` | — | Боевой сайт + сборка APK (TWA через Bubblewrap) |
| `kip8test-desktop` | Electron | — | `2.1.7` | Тестовый десктоп (зеркало kip8test) |
| `kip8-desktop` | Electron | — | `2.1.7` | Боевой десктоп (зеркало kip8) |

**Поток изменений:**

1. Правки делаются в `kip8test` (PWA) или `kip8test-desktop` (Electron-специфичное)
2. После проверки переносятся в `kip8` (PWA) или `kip8-desktop` (Electron)
3. При пуше в `index.html` `kip8test` → автосинхронизация в `kip8test-desktop` через `sync-to-desktop.yml` (секрет `DESKTOP_SYNC_TOKEN`)
4. При пуше в `index.html` `kip8` → автосинхронизация в `kip8-desktop` тем же workflow
5. Кэш-версия в `sw.js` инкрементируется при любом изменении файлов приложения

**Ключевые отличия kip8 vs kip8test:**

- Пути в `manifest.json`: `/kip8/` vs `/kip8test/`
- Имена кэшей в `sw.js`: `kipia-v*` vs `kipia-test-v*`, `kipia-images-v3` vs `kipia-images-test-v3`

- Расписание cron: kip8 на 2 ч раньше kip8test (чтобы не дублировать запросы к Google Sheets)
- APK собирается только в `kip8` (TWA-манифест `io.github.bloknett_design.twa`)

**Ключевые отличия десктоп-репозиториев от PWA-репозиториев:**

- `index.html` — точная копия родительского PWA (синхронизируется автоматически, **НЕ редактировать вручную**)
- **НЕТ** `manifest.json`, `sw.js`, `.nojekyll`, `.well-known/` — PWA-файлы не нужны в Electron
- **НЕТ** `scripts/` — синхронизация данных идёт в PWA-репозиториях
- **СВОИ**: `electron/main.js` (точка входа Electron с `autoUpdater` + `cleanCacheOnStartup()`), `package.json` (appId, productName, version), `charts-desktop.js` (Task 146, только Electron), `devices-table-desktop.js` (Task 148, только Electron)

## Контекст

Ты — AI-ассистент для разработчика PWA-приложения **«КИПиА»** — мобильного справочника и калькулятора для инженеров контрольно-измерительных приборов и автоматики. Приложение работает офлайн (Service Worker + NetworkFirst для данных), устанавливается на телефон как нативное (TWA через Bubblewrap — только в боевом `kip8`), распространяется напрямую APK-файлом, а также собирается как Electron-десктоп (`kip8-desktop` / `kip8test-desktop`).

Приложение включает: систему доступа через Email+OTP (Apps Script + Google Sheets), 12 ролей пользователей, гостевой режим, инженерные калькуляторы (конвертер единиц, шкала-сигнал, расчёт погрешностей по ГОСТ 8.401-80, буйковые уровнемеры, датчики температуры, сужающие устройства), библиотеку документов, раздел **КИП ИОС** (приборы/блокировки/клапаны/регуляторы/проекты/кабельный журнал/план корпуса 114), раздел «Расходомеры хозрасчётные» (двусторонняя синхронизация с Google Sheets), секретные разделы (сапёр, телефонный справочник), админ-панель.

**Где ведётся активная разработка:** в `kip8test` (тестовый PWA) и `kip8test-desktop` (тестовый десктоп). В `kip8` (боевой PWA) и `kip8-desktop` (боевой десктоп) изменения попадают только после проверки в тестовом репозитории.

### Apps Script — серверная часть (НЕ в репозитории)

Код Apps Script (`Code.gs`, `Utils.gs`, `CableJournal.gs`, `Flowmeter.gs`, `FlowmeterArchive.gs`) **физически не находится** в репозиториях. Он редактируется напрямую в Google Apps Script Web App (script.google.com). В репозиториях хранится только URL `WEB_APP_URL` (в `index.html`, ~строка 18 630), а серверные `.gs` файлы — в `scripts/` как справочные копии.

**Важно про `electron/main.js`:**

- `cleanCacheOnStartup()` — **всегда** очищает SW + cacheStorage при запуске (без проверки версии). Без этого SW переживает обновление Electron и отдаёт закэшированный старый `index.html`. Уровень 1: `session.clearCache()` + `session.clearStorageData({origin, storages: ['serviceworkers', 'cachestorage']})`. Уровень 2 (после `dom-ready`): unregister SW + delete caches + reload с `?_nocache=ts`.
- `autoUpdater` из `electron-updater` — при запуске через 5 сек проверяет `latest.yml` с GitHub Releases. Если `version` > текущей → диалог «Доступна новая версия → Скачать». После скачивания: «Установить / Позже» → `quitAndInstall()` → перезапуск.
- `latest.yml` генерируется electron-builder **ТОЛЬКО при пуше тега `v*`**.
- Баг `isDesktop()` в Electron (Task 126): `window.matchMedia('(min-width: 1024px)').matches` иногда возвращает `false` в Electron. Решение: использовать CSS `@media (min-width: 1024px) + body:has(.page-content.active)` вместо JS-проверок.

<sec>InitSorted(mode) / <sec>RenderSorted(mode) / <sec>ToggleGroup(key) / <sec>RenderGroup(key)

## 🔐 Система доступа Email+OTP

### Архитектура

```
[Браузер PWA / Electron]
   ↓ fetch POST (Content-Type: text/plain;charset=utf-8)
   ↓ body: JSON.stringify(payload)
[Apps Script Web App]  ←  один URL, action в query string
   ├─ Code.gs (doGet, doPost — роутинг по action)
   ├─ Utils.gs (Admin-объект, общие функции, MailApp.sendEmail)
   ├─ CableJournal.gs (cableJournal-объект)
   └─ Flowmeter.gs / FlowmeterArchive.gs
   ↓
[Google Sheets — таблица пользователей, сессий, audit_log, кабелей, расходомеров]
```

**Почему `Content-Type: text/plain;charset=utf-8` (а НЕ `application/json`):** `application/json` — это "non-simple" Content-Type, который заставляет браузер отправлять **CORS-preflight (OPTIONS-запрос)**. Apps Script **не определяет `doOptions`** → `405 Method Not Allowed` → браузер блокирует POST → «Failed to fetch». `text/plain;charset=utf-8` — "simple" Content-Type, preflight не отправляется, POST идёт сразу. Тело запроса остаётся JSON-строкой, Apps Script парсит через `e.postData.contents` + `JSON.parse`.

### Флоу входа (2 шага)

1. **Шаг 1** — ввод email (`#authEmail`): валидация regex → `api('sendOTP', {email})` → Apps Script отправляет письмо с 6-значным кодом (MailApp.sendEmail) → переключение на Шаг 2
2. **Шаг 2** — ввод OTP (`#otp1`...`#otp6`): авто-переход фокуса, вставка из буфера (`autocomplete="one-time-code"`) → `api('verifyOTP', {email, code})` → сервер возвращает `{token, role, userId, email}` → клиент сохраняет token + кэш роли → `_applyRoleToUI()` → переход на `dashboard`

### Bootstrap стратегия (КРИТИЧНО — Task 33)

При загрузке страницы `KipAuth.bootstrap()` работает по стратегии:

1. **НЕТ ТОКЕНА** → ГОСТЕВОЙ РЕЖИМ (роль «Общий доступ», без heartbeat). **НЕ показывать экран входа принудительно.**
2. **ЕСТЬ ТОКЕН + ЕСТЬ КЭШ РОЛИ** → БЫСТРЫЙ ПУТЬ: мгновенно показать приложение с кэшированной ролью + запустить heartbeat + в ФОНЕ запросить `getCurrentUser` для проверки. Успех → обновить кэш; `session_expired` → тихий переход в гостевой режим; сетевая ошибка → оставить пользователя в приложении с кэшированной ролью.
3. **ЕСТЬ ТОКЕН, НО НЕТ КЭША** → МЕДЛЕННЫЙ ПУТЬ: ждём ответа сервера. `session_expired` → гостевой режим; сетевая ошибка → экран входа с текстом «Не удалось связаться с сервером...» (токен НЕ удаляем, чтобы пользователь мог обновить страницу).

### Классификация ошибок (КРИТИЧНО)

Все ошибки в `api()` помечаются `_kind`:
- `'NETWORK'` — `TypeError: Failed to fetch`, не-OK HTTP, HTML вместо JSON, таймаут, обрыв
- `'SERVER'` — корректный JSON с `data.ok === false` (например `session_expired`, `no_session`, бизнес-ошибка)

**Правило:** NETWORK-ошибки **НЕ** сбрасывают токен и **НЕ** разлогинивают. SERVER-ошибки `session_expired`/`no_session` → реальный logout → гостевой режим. `api()` делает 2 попытки с задержкой 1 сек **только** для NETWORK-ошибок.

### Что НЕ делать в системе auth

- ❌ Использовать `Content-Type: application/json` — сломает POST из-за CORS-preflight
- ❌ Сбрасывать токен при сетевой ошибке — пользователь потеряет сессию из-за временного сбоя
- ❌ Показывать экран входа принудительно после logout — пользователь переходит в гостевой режим
- ❌ Хранить пароли — система использует только OTP
- ❌ Сохранять OTP-коды на клиенте — код одноразовый, проверяется только на сервере

### Двусторонняя синхронизация «клиент ↔ Apps Script ↔ Google Sheets» (паттерн)

Используется для кабельного журнала и расходомеров хозрасчётных:

1. **Google Sheets** — таблица с данными (доступ «у кого есть ссылка» для чтения)
2. **Apps Script — X.gs** — серверный модуль: `list()`, `update*()`, `_requireRead()`, `_requireEdit()`, `audit()`
3. **Apps Script — Code.gs** — роутинг в `doPost()` по action (`x.list`, `x.update*`)
4. **scripts/X.gs** — справочная копия в репозитории (НЕ исполняется)
5. **scripts/sync-x.py** — Python-скрипт для офлайн-fallback (экспорт xlsx → JSON)
6. **data/x.json** — статический fallback для PWA
7. **XData модуль в `index.html`** — клиент: `init()`, `load()`, `renderList()`, `openDetail()`, `submitInput()`, `_canEdit()`

**Серверные готчи:**

- **Даты:** Apps Script получает Date objects через `new Date(year, month-1, day)` (месяцы 0-indexed!). Читать даты нужно через `_sheetToClientDate()` — преобразует Date в M/D/YYYY format. В Excel-форматах используется `datetime_to_serial()` — конвертация Excel-дат в числовые значения.
- **Content-Type:** `text/plain;charset=utf-8` — НЕ `application/json` (см. раздел auth)
- **Авторизация:** `_requireRead()` / `_requireEdit()` — проверка роли по `READ_ROLES` / `INPUT_ROLES`. Методы возвращают `{ok, ...}` — **без throw**.
- **Аудит:** `Utils.audit(user.email, 'X_ACTION', '', '', message)` для каждой операции записи.
- **Оптимистичное обновление UI:** клиент обновляет UI сразу, потом ждёт ответа сервера. При ошибке — откат.

### Чеклист: добавление нового раздела с двусторонней синхронизацией

1. Google Sheets: создать лист, раздать доступ «у кого есть ссылка»

## 🔐 Автономная работа с GitHub (при наличии токена)

### Условия активации режима

Если пользователь передал GitHub PAT (Personal Access Token) — можно работать автономно: клонировать, коммитить, пушить. **Без PAT — только чтение** (clone через https без авторизации).

### Безопасность токена (КРИТИЧНО)

- PAT хранится в `/home/z/.kip_pat` (права 600)
- В git remote URL вставляется временно: `https://bloknett-design:$(cat /home/z/.kip_pat)@github.com/bloknett-design/<repo>.git`
- **ПОСЛЕ ПУША — ОБЯЗАТЕЛЬНО** сбросить URL: `git remote set-url origin https://github.com/bloknett-design/<repo>.git`
- ❌ НЕ оставлять PAT в `.git/config` — он переживает сессию и утечёт
- ❌ НЕ печатать PAT в чат, не логировать, не коммитить
- ✅ PAT у пользователя нужно запрашивать заново в каждом новом чате (не переносится между сессиями)

### Обязательный workflow автономной задачи

1. **Получить PAT** от пользователя (в чате)
2. **Сохранить в `/home/z/.kip_pat`**: `echo 'ghp_...' > /home/z/.kip_pat && chmod 600 /home/z/.kip_pat`
3. **Клонировать/обновить репозиторий**: `git clone https://bloknett-design:$(cat /home/z/.kip_pat)@github.com/bloknett-design/<repo>.git /home/z/my-project/<repo>` (или `git pull` если уже есть)
4. **Сделать изменения** (правки кода, документации и т. д.)
5. **Проверить** локально: тесты, синтаксис, сборка
6. **Заккоммитить**: `git add . && git commit -m "<сообщение>"`
7. **Запушить**: `git push origin main`
8. **СБРОСИТЬ URL** (ОБЯЗАТЕЛЬНО): `git remote set-url origin https://github.com/bloknett-design/<repo>.git`
9. **Удалить PAT из config** (если остался): проверить `git config --get remote.origin.url` — URL не должен содержать токен
10. **Сообщить пользователю** результат: коммит, ссылку на GitHub, что URL сброшен

### Что НЕ делать в автономном режиме

- ❌ Пушить в `kip8` без проверки в `kip8test` (исключение — срочный хотфикс с разрешения пользователя)
- ❌ Менять `manifest.json`, пути, `isolateLocalStorage()` без явного разрешения
- ❌ Форсить push (`git push -f`) без явного разрешения
- ❌ Оставлять PAT в git config после завершения работы

### Git-автор коммитов

При автоматических коммитах (от GitHub Actions) автор: `kip-bot <bot@kip8test.local>` или `github-actions[bot]`. При ручных коммитах из чата — обычный `user.name` / `user.email` из git config.

### Формат коммит-сообщения

```
<type>: <краткое описание> (v<версия кэша>, Task <номер>)

<опционально: детали>
```

Типы: `feat` (новое), `fix` (багфикс), `refactor` (рефакторинг), `docs` (документация), `style` (стиль), `test` (тесты), `chore` (хозяйственное).
